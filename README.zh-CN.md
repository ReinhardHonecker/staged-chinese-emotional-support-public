# 分阶段中文情感支持对话系统

**一个围绕“这一轮该怎样回应”展开设计的中文 NLP 课程项目。**

[English](README.md) · [系统架构](docs/ARCHITECTURE.md) · [评测说明](EVALUATION.md) · [Q&A](docs/Q_AND_A.md) · [本地演示](docs/DEMO.md)

> 本项目仅用于教学、研究和本地演示，不提供心理治疗、危机干预或医疗诊断，也不能替代专业人员与紧急服务。

这是**离线课程原型的公开源码快照**，从已审查的私有基线 `98dea9a8ecc889687031da09b79977aecd007295` 导出到不含旧私有 Git 历史的新仓库。不分发实验性 `joblib` 权重、原始语料、教师标签缓存、本地报告或私人证据。公开代码不等于已取得被排除权重的再分发许可，也不代表完成真实服务商验收或获准运营面向公众的情感支持服务。

## 项目概述

情感支持对话并不只是“识别一种情绪，再生成一段听起来温暖的话”。在多轮交流中，系统首先要判断：用户此刻究竟需要什么，这一轮又应该完成什么任务。

有时，用户只是想把事情说出来，不希望立刻收到建议；有时，用户需要把已经发生的事情、对未来的担忧和当下感受分开；有时，用户已经从几个方向中选定一项，希望把它变成一个具体的小步骤。系统如果没有分清这些情况，即使回复足够流畅，也可能答非所需。

本项目把一次对话处理拆成几个相互衔接的环节：先分析用户当前的处境、情绪和支持需求，再确定本轮的对话阶段与回应策略；随后生成回复和可选的行动卡，经过检查后再更新会话状态。用户还可以查看并纠正系统的理解，使后续回应尽量建立在可确认的信息上。

应用使用 Python、Pydantic 和 Streamlit 实现。默认离线模式依靠本地规则和中文模板运行，不需要配置模型 API；在用户明确同意数据传输后，也可以接入兼容的在线模型服务，但这条可选路径尚未通过真实服务商验收。仓库保留了轻量策略分类实验的代码和历史结果，不包含训练好的权重。历史模型没有达到项目设定的启用门槛；公开包缺少该权重时使用规则策略。

## 核心思路

同一句“我最近很乱”，可能是在邀请系统继续听，也可能是在请求帮助梳理问题，或者表示用户此刻只想先缓下来。为了避免系统在错误的时机给建议，本项目把“理解输入”和“决定回应方式”分开处理：

1. **状态分析**：整理用户陈述的事件、担忧或解释、感受、支持意图、建议准备度和安全语境；
2. **阶段控制**：确定本轮以表达、梳理、支持、协商、行动还是安全处理为主；
3. **策略规划**：规定怎样完成本轮任务，并约束是否允许建议、最多提供几个方向、最多提出几个主要问题；
4. **回复生成**：通过本地模板或可选的在线模型，把计划落实为自然语言和行动卡；
5. **回复检查**：同时检查正文和行动卡，再把最终结果写入会话状态。

这里的 `facts` 字段并不表示程序已经核实现实世界中的事实。它记录的是**用户陈述中的事件信息**。例如：

> 项目截止是周五，我担心做不完，脑子很乱，帮我区分事实和担心。

| 输入内容 | 在系统中的含义 |
| --- | --- |
| 项目截止是周五 | 用户提供的事件信息 |
| 我担心做不完 | 对未来结果的担忧，不能据此认定项目一定无法完成 |
| 脑子很乱 | 用户对当前感受的描述 |
| 帮我区分事实和担心 | 用户在这一轮提出的请求 |

当信息不足时，相关字段可以为空，也可以留待下一轮澄清，而不是为了填满结构，把整段输入重复塞进多个字段。当前实现采用有限的规则处理，并不等同于通用中文语义理解。

## 支持方式与对话阶段

界面提供“倾诉、梳理、稳定、行动”四种支持方式；系统内部则使用六个对话阶段来描述每一轮的主要任务。

| 阶段 | 主要任务 |
| --- | --- |
| 表达（Express） | 继续听取用户刚刚提到的内容，不急着转向解决方案。 |
| 梳理（Organize） | 区分事件、担忧、感受与请求，并邀请用户确认。 |
| 支持（Support） | 回应用户的感受；在用户希望先缓下来时，提供简短、低负担的支持。 |
| 协商（Strategize） | 在用户愿意讨论建议时，比较不超过三个可选方向。 |
| 行动（Act） | 把明确的选择或行动请求整理成一个可执行的小步骤，并生成行动卡。 |
| 安全（Safety） | 暂停普通问题分析，转入本地固定的安全处理流程。 |

这些阶段不是必须依次走完的固定流程。用户可以直接选择当前需要的支持方式；安全相关信息则具有更高优先级。选择“行动”也不意味着系统会立刻替用户作决定：当用户还在比较方向时，系统会先进入协商，等选择明确后再形成行动。

正常界面始终会提供支持方式，并默认选择“倾诉”。评测中的“无模式阶段判断”会刻意移除这一提示，用来单独观察规则选择器的表现，因此不能与正常界面条件混为一谈。

## 主要功能

### 1. 多维状态分析与用户纠正

系统会整理主要困扰、主次情绪、支持意图、建议准备度、问题结构、安全语境和原文证据，而不是只返回一个情绪标签。

用户可以通过界面的理解反馈修改系统判断，也可以直接在对话中纠正，例如“不是难过，我是生气”。对于测试中已经覆盖的明确说法，本轮纠正会在自动推断之后生效，被否定的情绪以及与主情绪重复的次要情绪会被移除。下一轮仍会重新分析新的输入，不会因为一次纠正而永久固定用户状态。

### 2. 承接上一轮实际展示的选项

系统只保存上一轮最终回复中真正显示、并且能够完整解析的选项。用户随后说“我选第二个”时，程序会先确认这句话能否唯一对应仍然有效的列表，再据此生成行动。

如果没有有效列表、编号越界、选择被否定、指代含糊，或者选项中的关键限定无法完整保留，系统会先澄清。对于 `1.5 分钟`、`两分半钟` 等当前不支持的时长表达，程序也不会擅自改成整数分钟。

### 3. 可编辑、可下载的行动卡

行动阶段可以生成结构化卡片，记录具体动作、时间与地点、预计时长、完成标准、可能障碍、备用方案、回顾提示和当前状态。用户可以在界面中修改卡片，并下载为 JSON 文件。

正文和行动卡作为同一个结果接受检查，避免页面展示的建议与最终保存的动作来自不同候选。进入安全阶段后，普通行动卡会暂时从界面隐藏，但仍保留在当前会话中；恢复普通对话后可以再次显示。

### 4. 默认离线，可选在线

默认离线模式使用本地规则分析输入、选择阶段和策略，再由中文模板组织回复。它不需要模型凭据，适合复现处理流程、运行测试和体验主要交互。

在线模式支持 OpenAI 兼容的 Chat Completions 协议和 Anthropic Messages 协议。普通轮次可以由在线模型辅助状态分析、回复生成和检查；如果调用失败或返回结果不符合结构要求，系统会按照既有检查与回退规则处理。

是否调用在线模型，与是否使用学习型策略分类器，是两个独立设置。在线模型可以遵循规则选出的策略；本地策略分类器只预测策略类别，不负责生成回复。当前接口测试使用 mock，最终代码版本尚未完成真实服务商验收。

### 5. 安全语境与输出检查

系统会在普通长度截断之前，对清洗后的完整输入进行本地安全预检。当前轮次如果被识别为 S2～S4，会留在本地固定流程中，不进入普通在线分析。现有路径还区分本人、第三方、自伤和他伤等语境，并在安全阶段隐藏普通行动卡。

S0～S4 只是项目内部的安全路由状态，不是临床风险等级。识别依赖有限规则与测试样例，不能保证覆盖所有真实表达。

## 一次输入如何被处理

```text
用户输入与当前会话
  → 清洗输入，并对完整文本进行本地安全预检
  → 对普通输入应用长度限制，过滤可能发送给服务商的历史
  → 在本地分析，或在用户授权后调用在线模型辅助分析
  → 选择本轮阶段与策略，并处理仍然有效的选项引用
  → 生成回复和可选行动卡
  → 检查完整输出，确定最终结果
  → 更新会话状态，显示回复、理解反馈和行动卡
```

更完整的控制流程和模块职责见[系统架构](docs/ARCHITECTURE.md)。

## 安装与运行

建议使用 **Python 3.12**。克隆以下公开源码仓库即可；离线运行不需要模型凭据，也不要把凭据写进克隆地址。

```bash
git clone https://github.com/ReinhardHonecker/staged-chinese-emotional-support-public.git
cd staged-chinese-emotional-support-public
```

### Windows PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1
```

### macOS / Linux

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py --server.address 127.0.0.1
```

打开终端给出的 localhost 地址即可。首次体验可以保持模型配置为空，选择一种支持方式，并使用合成文本进行测试。程序不要求创建 `.env`，也不需要另行下载生成式模型。

这里的“离线”仅表示程序不调用外部模型；安装依赖仍然需要网络，也不代表整个操作系统处于隔离网络中。

需要测试在线模式时，在侧栏填写协议、API 地址、模型标识和 API Key，阅读数据传输说明并明确同意后再应用配置。请勿使用真实敏感经历测试第三方接口。具体示例见[本地演示](docs/DEMO.md)。

## 轻量策略分类实验

仓库保存了基于字符级 TF-IDF、结构化特征和逻辑回归的策略分类实验代码、来源与历史指标。实验用于预测“这一轮采用哪种支持策略”，不生成回复，也不负责安全路由。**公开仓库不包含训练好的权重。** 以下结果来自先前私有实验，不是本次重新训练或公开包运行学习模型的结果。

| 指标 | 结果 |
| --- | ---: |
| Accuracy | 0.5929 |
| Macro-F1 | 0.4973 |
| Weighted-F1 | 0.6530 |
| Top-2 Accuracy | 0.8490 |

项目把 Macro-F1 的启用门槛设为 0.55，历史结果 0.4973 未通过。较高的 Top-2 Accuracy 和较小的权重文件不能替代该门槛。公开包没有附带权重，学习模式按既有加载器行为回退到规则；不分发权重也避免了把尚未核清的再分发权利说成已经获得许可。数据来源、标签方式、类别分布和完整限制见[模型卡](MODEL_CARD.md)。

## 隐私、使用边界与许可

应用默认不把对话原文持久化写入磁盘。在线配置只在当前 Streamlit 会话中有效，并要求用户明确同意数据传输；撤回同意后，已保存的连接和 API Key 草稿会被清除。普通在线请求仍可能包含经过长度限制的当前输入、过滤后的近期历史，以及从对话推导出的结构化状态。详细数据流见[隐私与安全说明](PRIVACY_AND_SAFETY.md)。

当前实现还有以下限制：

- 规则无法完整处理复杂否定、转述、反讽、隐含意图和远距离指代；
- 选项解析采取保守策略，部分自然表达会多经过一轮澄清；
- 无模式阶段判断存在明显类别偏差；
- 学习型策略分类器没有通过启用门槛；
- 尚未完成最终代码版本的真实服务商验收、真实用户研究或临床验证；
- 合成测试与机械检查无法证明每一条回复都合适。
